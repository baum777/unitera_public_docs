# Pilot and production readiness

Status: `PUBLIC_STATUS`

**As of:** 25 September 2026

UNITERA remains in **pilot preparation**. Compared with the previous public snapshot, technical and product-side preparation is materially further along: the bounded pilot scope, commissioning, onboarding, governed workflows, evidence/recovery semantics, and web and native product surfaces now have verifiable implementation.

This is explicitly **not pilot activation** and not production authorization.

## Already materialized

The following maturity level is now supportable as a public claim:

- a versioned, bounded pilot scope with an explicit change boundary;
- guided onboarding and commissioning with qualitative readiness instead of artificial percentages;
- Work, Needs You, Chat and Quick Action grammar with separate authority boundaries;
- bounded web, desktop and mobile projections including resume, pause, and current/stale states;
- a materialized cross-surface presentation baseline for central states without treating it as complete end-to-end parity;
- separate decision, grant, execution, receipt, verification and reconciliation;
- recovery semantics that forbid blind retry after uncertain external effect;
- personal continuity and contribution preparation without collapsing personal continuity into institutional authority;
- materialized security classification and evidence qualification without deriving production enforcement from it.

## Still open before a real pilot start

A live pilot additionally requires current evidence for the concrete operating environment. This includes in particular:

- external systems that are actually reachable and currently admitted;
- representative end-to-end qualification of the cross-surface-bound work and continuity states;
- valid tenant- and resource-bound operating bindings;
- real end-to-end evidence for the external paths required by the pilot;
- current grant, pause, revocation, expiry and re-evaluation evidence at effectful boundaries;
- a guided real case with honest outcome evidence and recovery behavior;
- explicit activation of the exact displayed pilot scope.

If one of these prerequisites is missing, the affected function remains visibly not ready, blocked or preparation-only. An implemented path must not be presented as live merely because contract, fixture or simulation checks pass.

## Pilot experience

The owner-confirmed pilot direction remains mobile-first and focuses on understandable, bounded workflows rather than broad autonomous software control. Preparation includes:

- guided onboarding with understandable step-by-step documentation;
- a final test covering open, inspect, decide, observe outcome evidence and pause;
- a feedback and help channel plus regular joint reviews;
- a persistent human pause as a clear operating boundary;
- manual takeover when a dependent technical path cannot continue reliably;
- subsequent reconciliation so manually handled or uncertain effects are not executed twice.

Technical success is not automatically business success. Uncertain outcomes remain uncertain until sufficient evidence exists.

## Production boundary

Production is a separate maturity stage. Neither a green technical check, a materialized pilot path, a successful simulation nor a bounded live pilot automatically creates production autonomy.

This page does not publish engineering tickets, internal gates, vendor, credential, security or runtime bindings.
