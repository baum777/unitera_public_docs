# Glossar

| Begriff | Öffentliche Definition |
|---|---|
| **Company Brain** | Kontrolliertes Organisationswissen und Foundation-Kontext; die Autorität liegt außerhalb der Consumer-Runtime. |
| **KNOW** | Context Runtime: kompiliert ausreichenden, Tenant-gebundenen und provenienzbewussten Kontext. |
| **THINK** | Cognition Runtime: Analyse, Planung, Neuplanung, Findings und Action Proposals innerhalb begrenzter Compute-/Autonomiegrenzen. |
| **ACT** | Execution Control: bewertet und übermittelt kontrollierte Wirkungen über explizite Autoritäts- und Evidenzgrenzen. |
| **Action Proposal** | Cognition-Output, der eine Wirkung vorschlägt; keine Ausführungserlaubnis. |
| **Capability Request** | Anfrage zur Nutzung einer Capability; kein Grant. |
| **Capability Grant** | Explizite begrenzte Autorisierung, unter definierten Bedingungen fortzufahren. |
| **Receipt** | Evidenz, dass ein Ausführungsversuch oder eine Provider-Interaktion stattgefunden hat; kein Nachweis des Geschäftsergebnisses. |
| **Verification** | Unabhängige Bestimmung des maßgeblichen Ergebnisses oder Zustands nach der Ausführung. |
| **Tenant** | Institutionelle Sicherheits- und Autoritätsgrenze. |
| **Registry** | Repository-übergreifende Referenz-, Provenienz- und Adoptionsoberfläche; referenziert Autorität, erzeugt sie aber nicht. |
| **Public Projection** | Menschenlesbare, aus verifizierten Quellen abgeleitete Dokumentation ohne eigene Autorität. |
| **Source Pointer** | Expliziter Mechanismus zur Auswahl eines aktuellen Source Bundles oder Zustands; Pointer-Prüfung und Quellenmaterialisierung sind getrennt. |
| **Local Runtime Node** | Kandidat für eine kontrollierte lokale Deployment-/Vertrauensgrenze; Lokalität allein erzeugt kein Vertrauen. |
| **Personal Realm** | Owner-approved first-class personengebundene Kontinuitäts- und Isolationsdomäne für eine dauerhafte UNITERA-Beziehung; weder Company Tenant, Membership, PlatformPrincipal noch Authority Domain. |
| **Personal Domain** | Transition-/Alternativbegriff, superseded durch den Preferred Term **Personal Realm**. |
| **Personal Tenant** | Historischer Working Term für Personal Realm; für normative Nutzung nicht empfohlen, weil Tenant bereits die institutionelle Sicherheits- und Autoritätsgrenze bezeichnet. |
| **Companion** | Dauerhafte persönliche Interaktions- und Cognition-Projektion des Personal Realm; weder Company Brain, Membership Authority noch Capability Grant. |
| **Personal Memory** | Bewusst gespeicherte nutzergebundene Kontinuitätsinformation; weder Conversation History, Runtime State noch institutionelle Wahrheit. |
| **PersonalIdea** | Persönliche Möglichkeit/Richtung, die entwickelt werden oder in Circling eintreten kann; weder Claim noch Decision. |
| **PersonalConcept** | Entwickeltes persönliches Modell, Design oder Lösungskandidat; getrennt von canonical Terminology Concept Identity und institutionellem Claim. |
| **PersonalPlan** | Persönliche Planungsstruktur; weder Work Order noch Company Objective. |
| **Circling** | Owner-approved first-class Semantic Lifecycle/Relationship für Aufmerksamkeit ohne Commitment; kein universelles Container-Objekt, keine Priority, kein Work Order, Claim oder Decision. |
| **Contribution Proposal** | Personal-side Proposal, das der Companion vorbereiten darf; der Übergang in einen institutionellen Lifecycle braucht explizite User Confirmation. |
| **PersonalContextProjection** | Explizit user-autorisierte, Tenant-/Purpose-/Scope-/Time-bound Projektion ausgewählten persönlichen Kontexts; weder Raw Personal Memory noch Company Ownership. |
| **CrossBoundaryResidencyDecision** | Entscheidung darüber, ob company-derived Context im Personal Memory persistieren darf und unter welchen Restriktionen. |
| **Relationship Familiarity** | Wie gut der Companion eine Person kennt; darf Interpretation verbessern, erzeugt aber keine Permission. |
| **Qualification** | Evidenz zuverlässigen Companion-Verhaltens in einem definierten Capability-/Scope-Bereich; kann Promotion Eligibility tragen, ist aber keine Authority. |
| **Global Companion Autonomy Tier** | Maximales qualitatives Personal-Autonomy-Ceiling; autorisiert keine Capability direkt. |
| **Effective Capability Tier** | Runtime-attenuierte Autonomie, die für eine konkrete Capability/einen Scope aktuell nutzbar ist; nie über Capability Delegation oder Global Ceiling. |
| **Companion Shadow Guard** | Unabhängiger Anomaly-/Reasonableness-Guard für autonome effectful Companion Actions; darf einfrieren, verweigern, eskalieren oder einen bestehenden Authority-Pfad weiterlaufen lassen, erzeugt aber keine Authority. |
